# אימונים — יומן אימוני כוח אישי

אפליקציית PWA למשתמש יחיד. בלי הרשמה, בלי התחברות, בלי שרת.
כל הנתונים נשמרים במכשיר ב-IndexedDB, והאפליקציה עובדת לגמרי אופליין אחרי הטעינה הראשונה.

**הפיצ'ר המרכזי**: בכל שורת סט רואים מה עשית בפעם הקודמת באותו תרגיל — השדות מגיעים
ממולאים מראש, ורק מתקנים מה שהשתנה ומסמנים וי.

---

## הרצה מקומית

```bash
npm install
```

```bash
npm run dev
```

הכתובת שתוצג בטרמינל (בדרך כלל `http://localhost:5173`).

### לבדוק מהנייד באותה רשת Wi-Fi

```bash
npm run dev -- --host
```

Vite ידפיס כתובת `Network:` מסוג `http://192.168.x.x:5173`. פתח אותה בכרום בנייד.
שים לב: התקנה למסך הבית וה-service worker דורשים HTTPS או localhost, ולכן ההתקנה
האמיתית תעבוד רק אחרי העלאה (השלב הבא). לבדיקת ממשק זה מספיק.

### פקודות נוספות

```bash
npm run build
```

```bash
npm run preview
```

```bash
npm run icons
```

`icons` מייצר מחדש את אייקוני ה-PWA מתוך ה-SVG שב-`scripts/generate-icons.mjs`.
צריך להריץ אותו רק אם משנים את האייקון — הפלט כבר נמצא ב-`public/icons`.

## העלאה בחינם

שתי האפשרויות חינמיות לחלוטין לשימוש הזה. **Vercel** הכי מהיר.

### אפשרות א׳ — Vercel

1. העלה את התיקייה ל-GitHub:

```bash
git remote add origin https://github.com/<המשתמש-שלך>/workout-app.git
```

```bash
git push -u origin main
```

2. היכנס ל-[vercel.com](https://vercel.com) והתחבר עם חשבון GitHub.
3. לחץ **Add New… → Project**, בחר את המאגר `workout-app` ולחץ **Import**.
4. Vercel מזהה Vite לבד. ודא שמופיע:
   - Framework Preset: `Vite`
   - Build Command: `npm run build`
   - Output Directory: `dist`
5. לחץ **Deploy**. אחרי כדקה תקבל כתובת כמו `https://workout-app-xxxx.vercel.app`.

הקובץ `vercel.json` שבמאגר כבר מטפל בניתוב — בלעדיו רענון בכתובת כמו `/history`
היה מחזיר 404.

כל `git push` ל-`main` מפרסם גרסה חדשה אוטומטית.

### אפשרות ב׳ — Netlify

**עם GitHub:** היכנס ל-[netlify.com](https://netlify.com) → **Add new site → Import an
existing project** → בחר את המאגר. הקובץ `netlify.toml` שבמאגר כבר מגדיר את פקודת
הבנייה, את תיקיית הפלט ואת הניתוב, אז אין מה למלא.

**בלי GitHub (גרירה ושחרור):**

```bash
npm run build
```

גרור את תיקיית `dist` שנוצרה אל [app.netlify.com/drop](https://app.netlify.com/drop).
תקבל כתובת מיד. החיסרון: כל עדכון דורש בנייה וגרירה מחדש.

## התקנה למסך הבית (אנדרואיד / כרום)

1. פתח את הכתובת שקיבלת (חייבת להיות `https://`) בכרום בנייד.
2. תפריט שלוש הנקודות ⋮ ← **הוספה למסך הבית** / *Add to Home screen*.
   אם מופיע באנר **התקנת אפליקציה** בתחתית המסך — אפשר פשוט ללחוץ עליו.
3. אשר. אייקון יופיע במסך הבית.
4. פתח את האפליקציה מהאייקון. היא תיפתח במסך מלא בלי שורת הכתובת של הדפדפן.
5. פתח אותה פעם אחת עם אינטרנט כדי שה-service worker ישמור הכל, ומשם היא עובדת גם
   במצב טיסה.

**באייפון (Safari):** כפתור שיתוף ← *Add to Home Screen*. עובד, אבל אנדרואיד/כרום
הוא המסלול שנבדק.

### כדאי לעשות מיד אחרי ההתקנה

היכנס ל**הגדרות ← אחסון במכשיר ← בקש אחסון קבוע**. בלי זה, אם ייגמר המקום במכשיר
הדפדפן רשאי למחוק את הנתונים.

### עדכון גרסה

ה-service worker מוגדר ל-`autoUpdate`: פתיחה של האפליקציה כשיש אינטרנט מושכת את
הגרסה החדשה ומחילה אותה בפתיחה הבאה. הנתונים לא מושפעים מעדכון.

## גיבוי

**הגדרות ← ייצא גיבוי** מוריד קובץ `workout-backup-YYYY-MM-DD.json` עם כל הנתונים.
מומלץ אחת לכמה שבועות — הנתונים קיימים רק במכשיר.

בשחזור יש שתי אפשרויות:

| מצב | מה קורה |
|---|---|
| **מיזוג** | מוסיף רק רשומות שלא קיימות. מה שכבר במכשיר לא משתנה. |
| **החלפה מלאה** | מוחק הכל ושם במקום את תוכן הקובץ. |

לקובץ יש שדה `schemaVersion`. כשמבנה הנתונים ישתנה בעתיד, `migrateBackup` ב-
`src/services/backupService.ts` משדרג גיבויים ישנים אוטומטית — מוסיפים פונקציה אחת
ל-`MIGRATIONS` ומעלים את `CURRENT_SCHEMA_VERSION`.

## ארכיטקטורה

ארבע שכבות. כל שכבה מכירה רק את זו שמתחתיה, וה-UI לא נוגע ב-Dexie ישירות.

```
screens/ + components/     ←  React בלבד
        ↓
hooks/                     ←  useLiveQuery — הדבק היחיד בין React למסד
        ↓
services/                  ←  לוגיקה עסקית, בלי React
        ↓
repositories/              ←  CRUD טהור
        ↓
db/                        ←  Dexie: סכמה, טיפוסים, זריעה
```

```
src/
├─ db/            types.ts · db.ts · seed.ts · ids.ts
├─ repositories/  אחד לכל טבלה
├─ services/      sessionService · historyService · statsService · planService · backupService
├─ hooks/         useData · useRestTimer · useNow
├─ components/    ui · Sheet · ConfirmDialog · NumberStepper · ExercisePicker · LineChart
│  └─ session/    SetRow · SessionExerciseCard
├─ screens/       מסך לכל route
└─ lib/           format (he-IL) · oneRepMax · constants
```

### מודל הנתונים

| טבלה | תפקיד |
|---|---|
| `exercises` | מאגר התרגילים. תרגיל אף פעם לא נמחק — רק `isArchived`. |
| `workouts` | סוגי אימון ("דחיפה", "רגליים"). |
| `workoutExercises` | **התוכנית**: אילו תרגילים בכל אימון, בסדר, עם יעדים. |
| `sessions` | אימון שבוצע. `endedAt === null` ⇒ אימון פעיל. |
| `sessionExercises` | **צילום מצב** של התוכנית ברגע "התחל אימון". |
| `setLogs` | כל סט שנרשם. |

`sessionExercises` היא מה שמפריד בין תוכנית להיסטוריה: מרגע תחילת האימון הוא מנותק
מהתוכנית, ולכן שינוי יעדים, שינוי סדר, שינוי שם תרגיל או מחיקת תרגיל מהתוכנית לא
משנים אף אימון שכבר בוצע.

### החלטות מוצר

- **"הפעם הקודמת"** = האימון האחרון שנסגר שיש בו סט **מסומן** באותו תרגיל, בלי קשר
  לסוג האימון. סטי חימום לא נחשבים.
- **מילוי מראש**: סט מס' N נטען מסט העבודה N של הפעם הקודמת; סטים נוספים מהסט האחרון.
  הערך מוצג באפור ולא נשמר במסד עד שנוגעים בו או מסמנים וי — כך אין במסד אף פעם נתון
  שלא אישרת.
- **סטטיסטיקות** סופרות רק סטים מסומנים שאינם חימום. נפח = `Σ משקל × חזרות`.
- **1RM משוער** לפי Epley: `weight × (1 + reps/30)`.
- **טיימר המנוחה** שומר timestamp ולא ספירה לאחור, ולכן מדויק גם אחרי כיבוי מסך או
  רענון.
- **שמירה מיידית** אחרי כל שינוי. אין כפתור "שמור". סגירת הדפדפן באמצע אימון לא
  מאבדת כלום.
- **localStorage** משמש רק להעדפות תצוגה ולטיימר. נתוני אימון — IndexedDB בלבד.
